# Система управления клиникой

## О проекте

Учебный проект базы данных медицинской клиники, разработанный с использованием Oracle SQL и PL/SQL.

База данных предназначена для хранения и обработки информации о пациентах, врачах, медицинских приёмах, диагнозах, лекарствах, назначениях и платежах.

Проект создан для практического изучения Oracle SQL, PL/SQL и проектирования реляционных баз данных.

## Используемые технологии

- Oracle SQL
- PL/SQL
- Git
- GitHub

## Структура базы данных

В проекте используются следующие таблицы:

- `SPECIALIZATIONS` — специализации врачей
- `DOCTORS` — информация о врачах
- `PATIENTS` — информация о пациентах
- `APPOINTMENTS` — записи пациентов на приём
- `MEDICAL_RECORDS` — медицинские записи, диагнозы и лечение
- `MEDICATIONS` — информация о лекарствах
- `PRESCRIPTIONS` — назначения лекарств пациентам
- `PAYMENTS` — информация об оплате приёмов

## Связи между таблицами

Основные связи базы данных:

- `SPECIALIZATIONS` → `DOCTORS`
- `PATIENTS` → `APPOINTMENTS`
- `DOCTORS` → `APPOINTMENTS`
- `PATIENTS` → `MEDICAL_RECORDS`
- `DOCTORS` → `MEDICAL_RECORDS`
- `PATIENTS` → `PRESCRIPTIONS`
- `DOCTORS` → `PRESCRIPTIONS`
- `MEDICATIONS` → `PRESCRIPTIONS`
- `APPOINTMENTS` → `PAYMENTS`

## Представления

В проекте созданы следующие представления:

### `v_appointment_details`

Показывает подробную информацию о приёмах:

- пациент;
- врач;
- специализация;
- дата приёма;
- статус;
- примечание.

### `v_medical_records`

Показывает медицинскую информацию:

- пациент;
- врач;
- специализация;
- диагноз;
- лечение;
- дата записи.

## Хранимые процедуры

### `add_patient`

Добавляет нового пациента в базу данных.

### `create_appointment`

Создаёт новую запись пациента на приём к врачу.

### `cancel_appointment`

Отменяет запись на приём и проверяет, можно ли её отменить.

## Функции

### `get_total_revenue`

Возвращает общую сумму оплаченных платежей.

### `get_patient_age`

Рассчитывает возраст пациента на основе даты рождения.

## Триггеры

В проекте создан триггер, который запрещает изменить завершённый приём на другой статус.

Это позволяет дополнительно контролировать целостность данных на уровне базы данных.
